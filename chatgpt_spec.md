# First Incident Report (FIR) – API RP 754 Classification Format\
\
I recommend developing this as a **First Incident Notification & PSE Classification Form** for use across chemical, petrochemical, oil & gas and process industries.\
\
The objective should be more than simply reporting an incident. The form should collect sufficient information to:\
\
1. Establish whether an event actually occurred or was a near miss.\
2. Identify whether the event is process-safety-related or occupational-safety-related.\
3. Determine whether it qualifies as an API RP 754 Process Safety Event (PSE).\
4. Identify the applicable PSE Tier – Tier 1, Tier 2, Tier 3 or Tier 4.\
5. Capture the required data for severity, consequence and threshold assessment.\
6. Generate a preliminary classification, subject to verification by the Process Safety / HSE team.\
\
**Important:** The form should not allow the person reporting the incident to arbitrarily declare it a Tier 1 or Tier 2 event. The reporter provides facts; the classification logic applies API RP 754 criteria.\
\

\

  </box>\

### Section I – API RP 754 classification declaration\
\
The reviewer should answer these questions using the applicable edition of API RP 754.\
\
| No. | Classification test | Yes / No / Pending |\
|---|---|---|\
| 1 | Was there an unplanned or uncontrolled release of material from a process? | |\
| 2 | Did the release result in an employee / contractor days-away injury or fatality? | |\
| 3 | Did it result in hospital admission or fatality of a third party? | |\
| 4 | Was there an officially declared community evacuation or shelter-in-place? | |\
| 5 | Did fire or explosion damage meet the Tier 1 direct-cost threshold? | |\
| 6 | Did the release quantity meet the applicable Tier 1 threshold in any one-hour period? | |\
| 7 | Did the event result in a recordable employee / contractor injury? | |\
| 8 | Did fire or explosion damage meet the Tier 2 direct-cost threshold? | |\
| 9 | Was there a qualifying engineered pressure relief discharge with the applicable quantity and consequence? | |\
| 10 | Was there a qualifying upset emission from a permitted / regulated source with the applicable quantity and consequence? | |\
| 11 | Did the release quantity meet the applicable Tier 2 threshold in any one-hour period? | |\
\
**Classification rules:**\
\
- If a Tier 1 criterion is met, declare **Tier 1 PSE**.\
- If no Tier 1 criterion is met but a Tier 2 criterion is met, declare **Tier 2 PSE**.\
- If neither is met, assess the event against the applicable Tier 3 indicators.\
- Where there is no actual PSE but a credible potential event, record it under the company's Near Miss classification.\
- Where there is a management-system or barrier-performance deficiency, assess the applicable Tier 3 / Tier 4 indicator.\
\
A Tier 3 event is not simply a lower-severity Tier 2 event. It has its own indicator definitions and criteria.\
\
### Section J – Final incident category\
\
The form should generate one of the following declarations:\
\
| Category | Declaration |\
|---|---|\
| Category 1 | <badge color=\"success\">Tier 1 PSE</badge> Major process safety event |\
| Category 2 | <badge color=\"warning\">Tier 2 PSE</badge> Process safety event with lesser consequence |\
| Category 3 | <badge color=\"info\">Tier 3 Indicator</badge> Challenges to safety systems / other qualifying process safety indicators |\
| Category 4 | <badge color=\"discovery\">Tier 4 Indicator</badge> Operating discipline and management system performance |\
| Category 5 | <badge color=\"secondary\">Near Miss</badge> No qualifying actual PSE; credible potential incident |\
| Category 6 | <badge color=\"secondary\">Other Incident</badge> Actual incident not qualifying as an API RP 754 PSE |\
| Category 7 | <badge color=\"secondary\">Pending Classification</badge> Insufficient data / verification required |\
\
*The Near Miss and Other Incident categories are company reporting categories, not additional API RP 754 tiers.*\

## 3. Additional information that should be mandatory\
\
To avoid incorrect classification, I strongly recommend attaching the following supporting documents:\
\
- [ ] Photographs / videos of the incident.\
- [ ] P&ID showing the incident location.\
- [ ] Equipment / piping identification.\
- [ ] SDS of the released material.\
- [ ] Release quantity calculation.\
- [ ] Relevant operating parameters and trends.\
- [ ] Alarm and event log.\
- [ ] SIS / ESD / PRV activation records.\
- [ ] Injury and medical treatment records, where applicable.\
- [ ] Fire / explosion damage cost assessment.\
- [ ] Emergency response report.\
- [ ] Evacuation / shelter-in-place declaration, where applicable.\
\
## 4. Important update – API RP 754 Fourth Edition\
\
<badge color=\"success\">Current edition: 4th Edition – 6 August 2026</badge>\
\
One important point for implementation: API published the **fourth edition on 6 August 2026**. It includes changes to direct-cost thresholds for Tier 1 and Tier 2, updated guidance for assessing fires, explosions and unignited releases, and expanded data collection requirements. Therefore, do not hard-code the old third-edition monetary thresholds into your form. <Cite refs={[\"turn213341search0\",\"turn213341search1\"]}/>\
\
Official reference: <Link ref=\"turn213341search0\" title=\"API RP 754 – Fourth Edition\"/>.\
\
I recommend maintaining a controlled classification master containing:\
\
- Material threshold release categories and quantities.\
- Tier 1 and Tier 2 direct-cost thresholds.\
- Injury and fatality criteria.\
- PRD / engineered pressure relief discharge criteria.\
- Permitted / regulated source emission criteria.\
- Tier 3 and Tier 4 indicator definitions.\
\
The classification engine should use the applicable fourth-edition criteria, with the standard's detailed definitions and exclusions verified by the Process Safety team.\
